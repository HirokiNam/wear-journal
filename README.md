# Wear Journal v2.0

靴から始めて、ジャケット・パンツなどにも拡張できる、端末内保存の個人用着用ログです。

## 使い始める前に

- このアプリは静的なHTML/CSS/JavaScriptだけで動きます。
- 画面やプログラムはGitHub Pages上で公開されますが、登録した名前・着用日・メモは通常その端末のブラウザ内（localStorage）に保存され、GitHubへ自動送信しません。
- 同じURLを夫婦それぞれの端末で開けば、データは基本的に別々です。同じ端末・同じブラウザ・同じURLでは共有されます。
- データは自動的にはiCloudへ同期されません。必ず定期的にJSONバックアップを保存してください。
- Safariで開いた画面とホーム画面に追加したアプリで保存領域が別になる場合があります。利用場所を決め、切り替えるときはJSONで移行してください。

## GitHub Pagesで公開する

1. GitHubで公開リポジトリ `wear-journal` を作成します。無料プランなら **Public** が必要です。
2. このZIPをiPhoneの「ファイル」アプリで解凍します。
3. リポジトリをSafariで開き、`Add file` → `Upload files` から、**解凍したフォルダの中身**をアップロードします。ZIPファイルだけをアップロードしてもサイトは動きません。
4. 必要なファイル：`index.html`、`app.js`、`style.css`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png`。`README.md` と `.nojekyll` も一緒にアップロードして構いません。ファイルは `wear-journal` リポジトリの最上位に置きます。
5. `Commit changes` を押します。
6. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Source: Deploy from a branch` を選び、`Branch: main / (root)` にして保存します。
7. 数分後に `https://あなたのユーザー名.github.io/wear-journal/` で開けます（ユーザー名やリポジトリ名に合わせて読み替えてください）。
8. iPhoneのSafariで開き、共有メニューから「ホーム画面に追加」します。

## アプリの使い方

1. 「アイテム」タブで靴を登録します。最初は靴だけが有効です。
2. 「カレンダー」で日付を選んで履いた靴をタップします。
3. 使わなかった日は「靴を履かなかった日」を選ぶと、未記録日と区別できます。
4. ジャケットやパンツの記録を始めたくなったら、「設定・バックアップ」→「使うカテゴリー」で追加します。
5. 名前を変えたり「引退」にしても着用履歴は残ります。

## JSONをiCloud Driveに保存する

1. 「設定・バックアップ」→「共有して保存」を押します。
2. iPhoneの共有メニューで「ファイルに保存」が使える場合、それを選び、保存場所に **iCloud Drive** を指定してください。
3. 使えない場合は「JSONを書き出す」を押し、ダウンロードしたJSONをiPhoneの「ファイル」から **iCloud Drive** へ移動してください。
4. おすすめは月1回のバックアップ＋大きなアプリ更新の直前です。
5. ご夫婦でバックアップを混同しないよう、`iCloud Drive/Wear Journal/本人`、`iCloud Drive/Wear Journal/妻` など別のフォルダを使用してください。
6. バックアップは完全に保存されたことを「ファイル」アプリで確認してください。アプリ内の「書き出し日時」は実際のiCloud保存を保証するものではありません。

## データの互換性とアップデート

- v2.0の保存形式は `schemaVersion: 2` で、服を共通の `items` にまとめ、日付ごとの `entries` はアイテムIDを記録します。
- v1の Shoe Journal の記録が**同じGitHub Pages URL / 同じ保存領域**に残っていれば、v2初回表示時に新形式へ移行します（旧キーは消さずに残します）。
- v1の JSON は、v2の「JSONから復元」からも取り込めます。
- 復元は**現在のデータを置き換えます**。ご夫婦のデータを統合する機能はありません。
- 更新時はGitHubに新しいコードを上書きします。記録は別保存ですが、ブラウザのデータ消去、URL/ドメイン変更、ストレージ制限などで失われる可能性があるため、必ず更新前にバックアップしてください。
- 将来 v3 以降で保存形式を変更するときは、旧データからの移行処理を追加する必要があります。コードの更新だけで将来永遠の互換性を保証するものではありません。
- CSVは表計算ソフト用で、復元には使用できません。

## 安全上の注意

- 認証はありません。GitHub Pagesのサイトとソースコードは一般に公開されます。
- 現状は第三者のコード・分析サービス・外部APIを読み込まず、アプリコードから記録データを送信しません。ただしGitHub Pagesへのアクセスに伴うIPアドレス等の通信情報はサービス側で扱われます。
- 公開するコード・READMEに本名、住所、私的な購入履歴やバックアップJSONなどを追加しないでください。
- 将来追加するコードが変わると、端末内の記録を読み取ったり外部送信したりできる可能性があります。変更内容を確認して公開してください。
